# Допущения
- При создании задач с помощью генератора используется файл, в котором заранее прописан список возможных задач
- Для создания задач из файла используется заранее добавленный в директорию json-файл
- Пользователь может создать вручную столько задач, сколько заранее напишет 
- Для завершения работы программы необходимо ввести число 7
- Для того, чтобы посмотреть функционал 4 лабораторной, нужно создать задачи с помощью любого из 3х методов создания задач, затем запустить асинхронное исполнение с помощью команды 6.
- Реализовано 3 обработчика - простой обработчик с логированием начала и конца выполнения каждой задачи (каждая задача в нем выполняется по 0.3 секунды); обработчик, который обрабатывает задачи в зависимости от их приоритета - чем выше приоритет, тем быстрее выполнение; обработчик для демонстрации обработки ошибок - при выполнении каждой 2-й задачи поднимается искусственно созданная ошибка.
- Задачи можно отфильтроавать по приоритету и статусу, а также по обоим этим параметрам вместе. 
- Пользователь не может изменить id, время создания задачи - при попытке их изменить пользователь увидит ошибку
- Пользователь может изменить payload (описание задачи, им должрна быть непустая строка); priority (приоритет - по умолчанию 3, может быть любое целое число от 1 до 5); status (статус задачи: "uncompleted", "in_progress", "done" или "cancelled", по умолчанию ставится uncompleted)
- При вводе некорректных данных для изменения одного из атрибутов задачи пользователь увидит ошибку
- Количество воркеров по умолчанию - 2



# Алгоритм работы

Вначале в файле handlers.py настраивается логирование: единый формат с временем и уровнем, все сообщения выводятся через logger. Дальше описывается контракт TaskHandlerProtocol — любой класс с асинхронным методом handle(task) считается обработчиком, @runtime_checkable позволяет проверять это через isinstance во время выполнения. Затем реализованы три обработчика:

**PrintHandler** логирует начало и конец с паузой 0.3 секунды
**PriorityHandler** вычисляет задержку как приоритет × 0.1, то есть чем выше приоритет, тем быстрее выполнение
**FaultyHandler** считает вызовы и падает с ошибкой на каждом втором для демонстрации обработки ошибок

Класс AsyncTaskExecutor проверяет контракт обработчика и создаёт asyncio.Queue. При входе в async with запускает фоновые воркеры(по умолчанию количество воркеров - 2). Метод submit кладёт задачу в очередь. Каждый воркер забирает задачу, передаёт обработчику, при ошибке логирует её и продолжает работу, в конце помечает задачу выполненной. При выходе из async with исполнитель дожидается завершения всех задач и прекращает работу.
